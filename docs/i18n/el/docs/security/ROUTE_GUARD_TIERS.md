## Επισκόπηση

Όλες οι διαδρομές του API διαχείρισης του OmniRoute ταξινομούνται σε ένα από τρία επίπεδα
προστασίας. Η ταξινόμηση είναι στατική, ορίζεται στο `src/server/authz/routeGuard.ts`
και αξιολογείται πριν εκτελεστεί οποιοσδήποτε άλλος κλάδος ελέγχου ταυτότητας.

## Επίπεδα

### Επίπεδο 1 — LOCAL_ONLY

**Επιβάλλεται από:** `isLocalOnlyPath(path)` → έλεγχος κεντρικού υπολογιστή loopback
**Παράκαμψη:** Καμία από προεπιλογή. Περιορισμένη εξαίρεση για διαδρομές στο
`LOCAL_ONLY_MANAGE_SCOPE_BYPASS_PREFIXES`, όταν το αίτημα περιλαμβάνει έγκυρο
κλειδί API με το scope `manage` (βλ. [Εξαίρεση για το scope manage](#manage-scope-carve-out)).

Αυτές οι διαδρομές δημιουργούν θυγατρικές διεργασίες ή εκτελούν κώδικα κατά τον χρόνο εκτέλεσης. Η έκθεσή τους σε
κίνηση εκτός loopback θα επέτρεπε σε έναν επιτιθέμενο που απέκτησε ένα έγκυρο JWT (π.χ.
μέσω μιας σήραγγας Cloudflared/Ngrok) να ενεργοποιήσει τη δημιουργία διεργασιών — μια γνωστή κατηγορία
CVE ([GHSA-fhh6-4qxv-rpqj](https://github.com/advisories/GHSA-fhh6-4qxv-rpqj)).

**Τι είναι το GHSA-fhh6-4qxv-rpqj (η κατηγορία επίθεσης):** ένας διακομιστής διαχείρισης/agent
εκθέτει ένα endpoint που εκκινεί μια υποδιεργασία (`npm install`, `node`, ένα πρόγραμμα περιήγησης,
έναν διακομιστή μεσολάβησης, `git`, `tar`, …). Εάν αυτό το endpoint είναι προσβάσιμο εκτός του κεντρικού υπολογιστή — επειδή
ο διαχειριστής τοποθέτησε το OmniRoute πίσω από μια σήραγγα nginx/Cloudflare/Tailscale και διέρρευσε ένα JWT
ή ο έλεγχος ταυτότητας είχε ρυθμιστεί εσφαλμένα — ο επιτιθέμενος μετατρέπει την «κλήση ενός API» σε «εκτέλεση μιας
εντολής στον κεντρικό υπολογιστή» (απομακρυσμένη εκτέλεση κώδικα). Το OmniRoute αποτρέπει αυτό το ενδεχόμενο επιβάλλοντας
**έλεγχο κεντρικού υπολογιστή loopback χωρίς εξαιρέσεις, πριν από οποιονδήποτε έλεγχο ταυτότητας**, σε κάθε
διαδρομή που μπορεί να δημιουργήσει διεργασίες: ένα διαρρεύσαν token μέσω μιας σήραγγας εξακολουθεί να μην μπορεί να φτάσει στη λειτουργία δημιουργίας διεργασιών.

**Το πλήρες σύνολο LOCAL_ONLY.** Η επίσημη πηγή είναι τα
`LOCAL_ONLY_API_PREFIXES` / `LOCAL_ONLY_API_PATTERNS` στο
`src/server/authz/routeGuard.ts`· ο παρακάτω πίνακας αντικατοπτρίζει την τρέχουσα κατάσταση. Η
πύλη `check-route-guard-membership` απαριθμεί κάθε `route.ts` κάτω από τα
προθέματα που μπορούν να δημιουργήσουν διεργασίες και προκαλεί αποτυχία του CI εάν κάποιο από αυτά δεν έχει ταξινομηθεί ως αποκλειστικά τοπικό.

#### Εξαίρεση για scope διαχείρισης

Ένα υποσύνολο διαδρομών LOCAL_ONLY ΜΠΟΡΕΙ επίσης να προσπελαστεί εκτός loopback, εάν και
μόνο εάν το αίτημα περιλαμβάνει ένα `Authorization: Bearer <api-key>` του οποίου
τα μεταδεδομένα περιλαμβάνουν το scope `manage` (ή `admin`). Η εξαίρεση ενεργοποιείται
ρητά ανά διαδρομή μέσω του `LOCAL_ONLY_MANAGE_SCOPE_BYPASS_PREFIXES`, ώστε η
προεπιλογή για κάθε νέα διαδρομή LOCAL_ONLY να παραμένει αυστηρά loopback. Τα μη αυθεντικοποιημένα
αιτήματα και τα αιτήματα με κλειδιά χωρίς δικαιώματα διαχείρισης εξακολουθούν να απορρίπτονται με
`403 LOCAL_ONLY`.

Προς το παρόν, το μόνο πρόθεμα που μπορεί να παρακάμψει τον περιορισμό είναι το `/api/mcp/`. Τα `/api/cli-tools/runtime/` και
`/api/services/` εξαιρούνται σκόπιμα, επειδή μπορούν να δημιουργήσουν αυθαίρετες
υποδιεργασίες (`npm install`, `node`), κάτι που αποτελεί ακριβώς την κατηγορία CVE την οποία
έχει σχεδιαστεί να αποτρέπει το επίπεδο LOCAL_ONLY.

**#7895 — περιορισμένο scope `mcp:connect`:** η εξαίρεση `/api/mcp/` δέχεται ΕΠΙΣΗΣ
ένα κλειδί Bearer που διαθέτει το περιορισμένο scope `mcp:connect`
(`src/shared/constants/managementScopes.ts::MCP_CONNECT_SCOPE`), το οποίο ελέγχεται μέσω
του `hasMcpConnectOrManageScope()` στο `src/server/authz/policies/management.ts`.
Αυτό περιορίζεται ΜΟΝΟ στο `/api/mcp/` — το `mcp:connect` δεν παρέχει κανένα δικαίωμα σε οποιαδήποτε άλλη
διαδρομή διαχείρισης (συμπεριλαμβανομένων όλων των άλλων προθεμάτων παράκαμψης LOCAL_ONLY, εάν
προστεθεί ποτέ κάποιο) και εξαιρείται σκόπιμα από το
`MANAGEMENT_API_KEY_SCOPES`. Ένα κλειδί που διαθέτει `manage`/`admin` εξακολουθεί να περνά την
εξαίρεση ακριβώς όπως πριν· το `mcp:connect` αποτελεί εναλλακτική χαμηλότερων προνομίων
για απομακρυσμένους καλούντες αποκλειστικά MCP, οι οποίοι δεν θα πρέπει να χρειάζονται ευρεία πρόσβαση διαχείρισης.

| Αίτημα                                              | Διαδρομή                   | Αποτέλεσμα                                 |
| --------------------------------------------------- | -------------------------- | ------------------------------------------ |
| Εκτός loopback, χωρίς Bearer                        | `/api/mcp/*`               | 403 LOCAL_ONLY                             |
| Εκτός loopback, Bearer με scope `manage`            | `/api/mcp/*`               | Επιτρέπεται                                |
| Εκτός loopback, Bearer με scope `mcp:connect`       | `/api/mcp/*`               | Επιτρέπεται                                |
| Εκτός loopback, Bearer χωρίς `manage`/`mcp:connect` | `/api/mcp/*`               | 403 LOCAL_ONLY                             |
| Εκτός loopback, Bearer με scope `mcp:connect`       | `/api/cli-tools/runtime/*` | 403 LOCAL_ONLY                             |
| Εκτός loopback, Bearer με scope `manage`            | `/api/cli-tools/runtime/*` | 403 LOCAL_ONLY                             |
| Loopback, με οποιοδήποτε/χωρίς Bearer               | οποιοδήποτε LOCAL_ONLY     | Επιτρέπεται (η πύλη επιτρέπει τη διέλευση) |

#### Οδηγίες για διαχειριστές & έλεγχος

Εάν εκτελείτε το OmniRoute πίσω από reverse proxy ή tunnel (nginx, Caddy, Cloudflare
Tunnel, Tailscale, Ngrok), ο έλεγχος loopback εξακολουθεί να προστατεύει τις παραπάνω
διαδρομές που μπορούν να δημιουργούν διεργασίες — ένα αίτημα του οποίου η διεύθυνση client δεν είναι loopback απορρίπτεται με
`403 LOCAL_ONLY` **πριν εκτελεστεί ο έλεγχος ταυτότητας**, επομένως ένα JWT που έχει διαρρεύσει δεν μπορεί να προκαλέσει δημιουργία διεργασίας. Παραμένουν δύο
ευθύνες για τους διαχειριστές:

- **Μην «διορθώνετε» ένα 403 πλαστογραφώντας τη διεύθυνση IP του πελάτη ως loopback.** Ο ορισμός
  `X-Forwarded-For: 127.0.0.1` ή η χρήση διακομιστή μεσολάβησης που επανεγγράφει τη διεύθυνση προέλευσης ως
  loopback επανεκθέτει ακριβώς την κατηγορία RCE που αποκλείει αυτό το επίπεδο. Εκθέστε τον
  πίνακα ελέγχου/API μέσω του διακομιστή μεσολάβησης — ποτέ τις διαδρομές με δυνατότητα εκκίνησης διεργασιών.
- **Διατηρήστε ελάχιστη την παράκαμψη βάσει εμβέλειας `manage`.** Μόνο το `/api/mcp/` μπορεί να παρακαμφθεί και
  μόνο με ένα κλειδί API εμβέλειας `manage`. Τα `SPAWN_CAPABLE_PREFIXES` δεν μπορούν ποτέ να
  προστεθούν στη λίστα παράκαμψης — το σχήμα zod τα απορρίπτει και το
  `isLocalOnlyBypassableByManageScope` τα αποκλείει κατά την εκτέλεση (άμυνα σε βάθος),
  κάτι που εννοεί ο πίνακας ελέγχου με τη φράση «δεν μπορεί να καταστεί παρακάμψιμο». Ο φορτωτής στιγμιότυπων
  κατά την εκτέλεση αφαιρεί επίσης τέτοιες καταχωρίσεις από μια αποθηκευμένη γραμμή ρυθμίσεων, ενώ η
  εισαγωγή παλαιού τύπου JSON (`/api/settings/import-json`) δεν εγγράφει ποτέ τα κλειδιά παράκαμψης.
  Κάθε καταχώριση `LOCAL_ONLY_API_PREFIXES` πρέπει είτε να βρίσκεται στη λίστα αποκλεισμού είτε
  να έχει ελεγχθεί ως κατάλληλη για παράκαμψη (`tests/unit/authz/local-only-bypass-spawn-denylist.test.ts`). Οι διαδρομές
  με δυναμικά τμήματα και στατικές διαδρομές με δυνατότητα εκκίνησης διεργασιών κάτω από το `/api/providers/` (π.χ. `/login`,
  `/refresh-cursor`) καλύπτονται από τα συνοδευτικά `SPAWN_CAPABLE_PATTERNS` /
  `SPAWN_CAPABLE_PATTERN_ANCESTORS` που βασίζονται σε κανονικές εκφράσεις στο
  `src/shared/constants/spawnCapablePrefixes.ts`, όχι από τον επίπεδο πίνακα
  `SPAWN_CAPABLE_PREFIXES` — ο επίπεδος πίνακας θα έπρεπε να καλύπτει ολόκληρο το
  πρόθεμα `/api/providers/` για να τις εντοπίζει, διευρύνοντας υπερβολικά ένα δέντρο διαδρομών
  που οι απομακρυσμένοι πίνακες ελέγχου χρησιμοποιούν εύλογα για λειτουργίες CRUD παρόχων.

**Έλεγχος πρόσβασης** — για να επαληθεύσετε ότι τίποτα εκτός κεντρικού υπολογιστή δεν φτάνει σε αυτές τις διαδρομές:

- Ανοίξτε το **Απόθεμα εξουσιοδότησης** στη διεύθυνση `/dashboard/settings/security`: εμφανίζει τη
  ζωντανή λίστα προθεμάτων LOCAL_ONLY, ποια προθέματα μπορούν να παρακαμφθούν και το σύνολο
  με δυνατότητα εκκίνησης διεργασιών («δεν μπορεί να καταστεί παρακάμψιμο») που καθορίζεται κατά τη μεταγλώττιση.
- Αναζητήστε στα αρχεία καταγραφής του reverse proxy / πρόσβασης τα παραπάνω προθέματα σε συνδυασμό με μια
  διεύθυνση πελάτη που δεν είναι loopback. Οποιοδήποτε τέτοιο αίτημα επέστρεψε `200` αντί για
  `403 LOCAL_ONLY` σημαίνει ότι ο διακομιστής μεσολάβησης αποκρύπτει την πραγματική IP του πελάτη — διορθώστε τον διακομιστή μεσολάβησης.
- Ένα `403 LOCAL_ONLY` στα αρχεία καταγραφής του OmniRoute για μία από αυτές τις διαδρομές σημαίνει ότι ο μηχανισμός προστασίας
  λειτουργεί όπως προβλέπεται· δεν είναι σφάλμα που πρέπει να κατασταλεί.

### Επίπεδο 2 — ALWAYS_PROTECTED

**Επιβάλλεται από:** `isAlwaysProtectedPath(path)` → παράλειψη της παράκαμψης `requireLogin=false`
**Παράκαμψη:** Καμία όταν `requireLogin=false`· απαιτείται πάντα JWT

Αυτές οι διαδρομές είναι καταστροφικές ή μη αναστρέψιμες. Αν επιτρέπονταν σε μια εγκατάσταση
«χωρίς κωδικό πρόσβασης», οποιοσδήποτε στο ίδιο LAN θα μπορούσε να διαγράψει τη βάση δεδομένων ή να τερματίσει τη
διεργασία του διακομιστή.

| Διαδρομή                                  | Αιτία                                                                         |
| ----------------------------------------- | ----------------------------------------------------------------------------- |
| `/api/shutdown`                           | Τερματίζει τη διεργασία του διακομιστή                                        |
| `/api/settings/database`                  | Εξαγωγή, εισαγωγή και διαγραφή βάσης δεδομένων                                |
| `/api/db-backups`                         | Πρόσβαση σε πλήρες αρχείο αντιγράφου ασφαλείας της βάσης δεδομένων            |
| `/api/settings/export-json`               | Εξάγει το πλήρες σύνολο ρυθμίσεων (συμπερ. μυστικών)                          |
| `/api/settings/import-json`               | Αντικαθιστά το πλήρες σύνολο ρυθμίσεων                                        |
| `/api/providers/health-autopilot/actions` | Εκτελεί ενέργειες αποκατάστασης του autopilot                                 |
| `/api/settings/obsidian`                  | Εκδίδει επαναχρησιμοποιήσιμα διαπιστευτήρια WebDAV για οποιαδήποτε ρίζα vault |

**Απόκριση σε περίπτωση παραβίασης:** `401 Authentication required`

Το `/api/settings/obsidian` καλύπτει το θυγατρικό του `/webdav`: το `POST` κατευθύνει την υπηρεσία αρχείων WebDAV —
η οποία εξυπηρετείται από το προσαρμοσμένο επίπεδο Node πριν από το Next.js, εκτός αυτής της διοχέτευσης — σε μια ρίζα
επιλεγμένη από τον καλούντα και επιστρέφει τα διαπιστευτήρια Basic που μόλις εκδόθηκαν, το `DELETE` τα ανανεώνει, ενώ το γονικό `POST` αποθηκεύει
το διακριτικό του Obsidian REST API. Το GHSA-62vw απέκρυψε μόνο την αποκάλυψη του κωδικού πρόσβασης μέσω `GET`· η έκδοση
παρέμενε στο επίπεδο ανοικτής πρόσβασης σε περίπτωση αποτυχίας (GHSA-7pq4-8pvv-rx7r). Το `enableObsidianVaultSync()` επιπλέον
απορρίπτει ένα vault που ταυτίζεται με τον κατάλογο δεδομένων, βρίσκεται μέσα σε αυτόν ή τον περιέχει.

### Η αρχικοποίηση νέας εγκατάστασης είναι διαθέσιμη μόνο μέσω loopback — βάσει του πραγματικού ομότιμου μέρους, όχι του `Host`

Όταν δεν έχει διαμορφωθεί κωδικός πρόσβασης διαχείρισης (και δεν υπάρχει `INITIAL_PASSWORD`), το `isAuthRequired()` στο
`src/shared/utils/apiAuth.ts` διατηρεί την ανώνυμη αρχικοποίηση ανοικτή **μόνο για ομότιμα μέρη loopback**.
Το loopback προσδιορίζεται από τα αξιόπιστα σήματα του ομότιμου μέρους, με την εξής σειρά: το πραγματικό ομότιμο μέρος TCP που έχει επισημανθεί με διακριτικό
(`PEER_IP_HEADER` + `VIA_PROXY_HEADER`, αυτό που βλέπει η πολιτική), την ετυμηγορία
`AUTHZ_HEADER_PEER_LOCALITY` της ίδιας της διοχέτευσης (αυτό που βλέπουν οι χειριστές διαδρομών, το οποίο θεωρείται αξιόπιστο μόνο όταν
έχει οριστεί το `OMNIROUTE_PEER_STAMP_TOKEN`) ή ένα πραγματικό ομότιμο μέρος υποδοχής για άμεσους καλούντες. Τα `Host` /
`nextUrl.hostname` δεν λαμβάνονται ποτέ υπόψη και η εγγραφή του πρώτου κωδικού πρόσβασης
(`POST /api/settings/require-login`) υπόκειται στον ίδιο περιορισμό αντί να είναι ανοικτή σε κάθε
ομότιμο μέρος του δικτύου (GHSA-7pq4-8pvv-rx7r). Το `managementPolicy` μεταβιβάζει ρητά τη δική του ετυμηγορία
`peerContext`, ώστε οι κεφαλίδες του ΑΡΧΙΚΟΥ αιτήματος (πριν από την αφαίρεσή τους) να μην την καθορίζουν ποτέ.

### Επίπεδο 3 — MANAGEMENT (προεπιλογή)

Όλες οι άλλες διαδρομές διαχείρισης. Απαιτείται έλεγχος ταυτότητας, εκτός εάν έχει
διαμορφωθεί `requireLogin=false`. Τα διακριτικά CLI μπορούν να πιστοποιούν αυτές τις διαδρομές (loopback + έγκυρο HMAC).

## Σειρά αξιολόγησης

```
managementPolicy.evaluate(ctx)
  1. isLocalOnlyPath(path)?
     → loopback                                  → συνέχισε στο επόμενο βήμα
     → non-loopback, Bearer με manage-scope
        ΚΑΙ isLocalOnlyBypassableByManageScope   → επέτρεψε (management_key)
     → διαφορετικά                               → απόρριψε με 403 LOCAL_ONLY
  2. isInternalModelSyncRequest(ctx)?
     → επέτρεψε (system)
  3. hasValidCliToken(headers)?
     → επέτρεψε (cli) [loopback + έλεγχος HMAC με timingSafeEqual]
  4. isAlwaysProtectedPath(path) ή requireLogin=true?
     → isDashboardSessionAuthenticated?
        → επέτρεψε (dashboard_session)
     → Bearer με manage-scope σε μη παρακάμψιμη διαδρομή;
        → επέτρεψε (management_key)
     → απόρριψε με 401/403
  5. requireLogin=false?
     → επέτρεψε (anonymous)
```

Ο κλάδος manage-scope του βήματος 1 είναι η μόνη αυθεντικοποιημένη διαδρομή που μπορεί να ικανοποιήσει μια διαδρομή
LOCAL_ONLY· σε περίπτωση αποτυχίας του auth-backend επιστρέφεται 503 (όχι 403), ώστε μια
ληγμένη DB να μην υποβαθμίζεται σιωπηρά σε "deny".

## Προσθήκη νέας διαδρομής με δυνατότητα spawn

1. Προσθέστε το πρόθεμα διαδρομής στο `LOCAL_ONLY_API_PREFIXES` στο
   `src/server/authz/routeGuard.ts`
2. Προσθέστε μια δοκιμή στο `tests/unit/authz/routeGuard.test.ts` που να επαληθεύει ότι το
   `isLocalOnlyPath()` επιστρέφει true για το νέο πρόθεμα
3. **Μην παραλείψετε ποτέ αυτό το βήμα** — δείτε τον Αυστηρό Κανόνα #15 στο `CLAUDE.md`
4. Αποφασίστε: ανήκει αυτή η διαδρομή ΕΠΙΣΗΣ στο `LOCAL_ONLY_MANAGE_SCOPE_BYPASS_PREFIXES`;
   Η προεπιλεγμένη απάντηση είναι **όχι**. Επιλέξτε το μόνο όταν η διαδρομή είναι ασφαλές να εκτεθεί σε έναν
   κάτοχο manage-scope (δηλαδή ΔΕΝ εκκινεί αυθαίρετο κώδικα ελεγχόμενο από τον χρήστη).

## Προσθήκη διαδρομής παρακάμψιμης μέσω manage-scope

1. Επιβεβαιώστε ότι η διαδρομή δεν εκτελεί κώδικα ή εντολές που παρέχονται από τον χρήστη. Αν το
   κάνει, σταματήστε — αυτή η εξαίρεση δεν είναι το κατάλληλο εργαλείο.
2. Προσθέστε το πρόθεμα στο `LOCAL_ONLY_MANAGE_SCOPE_BYPASS_PREFIXES` στο
   `src/server/authz/routeGuard.ts`
3. Προσθέστε κάλυψη στο `tests/unit/authz/management-policy.test.ts` και για τις τέσσερις
   μορφές αιτήματος: χωρίς Bearer (403), manage Bearer (επιτρέπεται), μη-manage Bearer
   (403), και τη δοκιμή παλινδρόμησης ανά πρόθεμα που διασφαλίζει ότι το `/api/cli-tools/runtime/*` παραμένει
   αυστηρά loopback ακόμη και με manage Bearer.

## Τεκμηρίωση επιπέδων ασφαλείας στο OpenAPI

Κατά την προσθήκη μιας νέας διαδρομής στο `docs/openapi.yaml`, εφαρμόστε την αντίστοιχη
επέκταση προμηθευτή, εάν η διαδρομή ταξινομείται από το `routeGuard.ts`:

| Ταξινόμηση routeGuard.ts       | Σχολιασμός YAML             | Επιβολή                                              |
| ------------------------------ | --------------------------- | ---------------------------------------------------- |
| `LOCAL_ONLY_API_PREFIXES`      | `x-loopback-only: true`     | Αποκλείεται άνευ όρων από non-loopback               |
| `ALWAYS_PROTECTED_API_PATHS`   | `x-always-protected: true`  | Απαιτείται auth ακόμη και με `requireLogin=false`    |
| Εσωτερική διαδρομή admin/debug | `x-internal: true`          | Κρυφή από το /dashboard/api-endpoints από προεπιλογή |
| Καμία (δημόσια / τυπικό auth)  | (δεν απαιτείται σχολιασμός) | Τυπική πρόσβαση ελεγχόμενη από το `requireLogin`     |

### Επικύρωση

Δύο scripts επιβάλλουν τη συνέπεια μεταξύ των σχολιασμών YAML και του `routeGuard.ts`:

- `scripts/check/check-openapi-coverage.mjs` — αποτυγχάνει αν η κάλυψη είναι < 99%
- `scripts/check/check-openapi-security-tiers.mjs` — αποτυγχάνει αν οι σχολιασμοί `x-loopback-only` ή
  `x-always-protected` αποκλίνουν από τις σταθερές χρόνου μεταγλώττισης

Και τα δύο scripts εκτελούνται στο pre-commit hook και στο CI.

### Κανόνας ψευδώς θετικών αποτελεσμάτων

Αν το `x-always-protected` ή το `x-loopback-only` έχει προστεθεί ως σχολιασμός σε μια διαδρομή που ΔΕΝ βρίσκεται στη
σταθερά του `routeGuard.ts`, το script κάλυψης αποτυγχάνει. Η διόρθωση είναι πάντα η ευθυγράμμιση του
YAML με ό,τι πραγματικά επιβάλλει το `routeGuard.ts` — όχι η προσθήκη διαδρομών στο `routeGuard.ts`
χωρίς να υλοποιηθεί επίσης η λογική επιβολής.
