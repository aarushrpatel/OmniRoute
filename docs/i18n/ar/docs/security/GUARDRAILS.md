> لم يتم التحقق منه من قبل الخادم بعد — تم توضيحه لكل #11661)

تفرض الحواجز (Guardrails) السلامة والسياسة وتحويلات المحتوى عند الحدود
بين OmniRoute ومقدمي الخدمة المصدر. يمكن لكل حاجز فحص (ورفض أو تحويل أو إضافة تعليق اختياريًا) حمولات الطلبات (`preCall`)
واستجابات المصدر (`postCall`).

النظام **مفتوح عند الفشل (fail-open)**: إذا ألقى حاجز خطأ أثناء التنفيذ، فإن السجل
يسجل الخطأ ويستمر مع الحاجز التالي بدلاً من إفشال الطلب.
المنع هو قرار صريح (`block: true`)، وليس حادثًا أبدًا.

## ضوابط الحماية المضمّنة

يحمّل السجل تلقائيًا ستة ضوابط حماية حسب ترتيب الأولوية عند الاستيراد
(راجع `registry.ts` ← `registerDefaultGuardrails()`):

| الأولوية | الاسم               | المرحلة (المراحل) | الملف                 |
| -------- | ------------------- | ----------------- | --------------------- |
| `5`      | `vision-bridge`     | `preCall`         | `visionBridge.ts`     |
| `6`      | `audio-bridge`      | `preCall`         | `audioBridge.ts`      |
| `7`      | `video-bridge`      | `preCall`         | `videoBridge.ts`      |
| `10`     | `pii-masker`        | `pre` + `post`    | `piiMasker.ts`        |

### جسر الرؤية (`visionBridge.ts`) — جسر الوسائط PR-1

يعترض الطلبات التي تحتوي على صور والموجّهة إلى **نماذج لا تدعم الرؤية**، ثم إما
يعيد توجيه الطلب بالكامل إلى نموذج يدعم الرؤية، أو يستبدل أجزاء الصور
بأوصاف نصية ينتجها نموذج رؤية قابل للتهيئة قبل
الاستدعاء إلى الخدمة المصدرية. يتيح ذلك لموفّري النماذج النصية فقط التعامل بشفافية مع
الحمولات متعددة الوسائط.

التدفق:

1. التخطي إذا كان النموذج المستهدف يدعم الرؤية بالفعل (إلا إذا كان موجودًا في
   قائمة الجسر الإلزامي `isVisionBridgeForcedModel`).
2. استخراج أجزاء الصور عبر `extractImageParts(messages)`
   (`visionBridgeHelpers.ts`)، التي تفوّض المهمة إلى **كاشف الوسائط
   الموحّد** `detectMediaParts()` في `open-sse/utils/mediaParts.ts` — وهو
   مصدر الحقيقة الوحيد المشترك مع مرشّح توافق المجموعة.
   يقتصر الاستخراج، وفق قائمة سماح، على الأجزاء ذات المستوى الأعلى التي يمكن
   لـ `replaceImageParts` إعادة إدراجها (عقد الاستخراج↔الاستبدال): تنسيق OpenAI
   ‏`image_url`، ومصدر Anthropic بترميز base64 من النوع `source.type:"base64"`، ومصدر Anthropic بعنوان URL
   من النوع `source.type:"url"`، وتنسيق Responses API ‏`input_image`. أما النتائج المتداخلة
   والأشكال التي تحتوي على مؤشرات فقط فهي مخصّصة لمرشّح المجموعة ولا تُستخرج أبدًا.
   يتم التخطي إذا لم يُعثر على أي منها.
3. تحليل إعدادات وقت التشغيل عبر `resolveVisionBridgeRuntimeSettings()`
   (`src/shared/constants/modalityBridgeDefaults.ts`): تكون الأولوية لمفاتيح إعدادات `modalityBridge*`
   الجديدة؛ بينما تظل مفاتيح `visionBridge*` القديمة **خيارًا احتياطيًا لدورة
   واحدة** (نافذة التراجع). يتم التخطي قبل أي اجتياز للوسائط عندما يكون
   الجسر معطّلًا.
4. يحدّد منتقي الوضع (`modalityBridgeVisionMode`، راجع الجدول أدناه)
   ما إذا كان سيتم إعادة التوجيه أم إنشاء وصف. تُرجع إعادة التوجيه `modifiedPayload` مع تبديل `model`
   فقط، إضافة إلى البيانات الوصفية `{ rerouted, fromModel, toModel, imagesKept }`.
5. مسار الوصف: يقيّد عدد الصور عند `maxImages`، ويُنشئ المطالبة المدركة للمهمة،
   ويراجع ذاكرة التخزين المؤقت للأوصاف، ويستدعي نموذج الرؤية **بالتوازي**
   (`Promise.allSettled`)، ثم يدرج أجزاء نصية بالشكل `[Image N]: <description>` في
   مواضعها. ينتج عن فشل الوصف `null` مع **الاحتفاظ** بجزء الصورة الأصلي
   (#4012) — باستثناء مسار وصف المجموعة عندما تفشل جميع
   عمليات الوصف؛ ففي هذه الحالة، تتلقى الخدمة المصدرية التي تأكد أنها لا تدعم الرؤية نصًا بديلًا
   `(غير متاح — لا يوجد موفّر يدعم الرؤية متصل)` بدلًا منه (#8430).
6. إرجاع `modifiedPayload` مع البيانات الوصفية (`imagesProcessed`، و`descriptions`،
   و`processingTimeMs`، و`visionModel`).

#### منتقي الوضع (`modalityBridgeVisionMode`)

| الوضع      | الافتراضي | السلوك                                                                                                                                                                                                                                                           |
| ---------- | --------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `auto`     | ✔         | آلية الاستدلال القديمة دون تغيير (#6640/#7204): تعيد النماذج غير المجمّعة/نماذج `auto/` التوجيه إلى أفضل نموذج رؤية، ما لم يكن النموذج الأصلي يمتلك بيانات اعتماد قابلة للاستخدام (وعندئذٍ يُنشئ وصفًا)؛ أما أهداف المجموعة فتنشئ وصفًا دائمًا.                  |
| `describe` |           | إنشاء وصف دائمًا — تُتخطى كتلة إعادة التوجيه بالكامل؛ ويجيب النموذج الذي اختاره المستخدم دائمًا.                                                                                                                                                                 |
| `reroute`  |           | فرض إعادة التوجيه: يتم تجاوز حاجز الاحتفاظ بالنموذج ذي بيانات الاعتماد. يظل حاجز بيانات اعتماد **هدف** إعادة التوجيه مطبّقًا — فعندما لا يتوفر هدف رؤية قابل للاستخدام، ينتقل الطلب إلى إنشاء الوصف كي لا تصل الصور الخام أبدًا إلى خدمة خلفية نصية فقط (#8430). |

تتجاوز الأوضاع المفروضة منطق الاستدلال التلقائي **قبل** تشغيله؛ ويظل سلوك `auto`
مطابقًا على مستوى البايت لضابط الحماية السابق لـ PR-1.

#### نطاق مفتاح API (`visionBridgeKeyScope.ts`)

عندما يقيّد مفتاح API الخاص بالمتصل `allowedConnections`، أو مجموعات الحصص
(`allowedQuotas`)، أو النماذج (`allowedModels` / `blockedModels` /
`modelAccessMode: "restricted"` / `disableNonPublicModels`)، لا يختار الجسر
لنماذج إعادة التوجيه والوصف إلا النماذج التي يسمح المفتاح باستخدامها، وعلى الاتصالات التي يسمح المفتاح
باستخدامها. يمر استدعاء الوصف بعد ذلك دائمًا عبر الحلقة الذاتية لـ OmniRoute باستخدام
الترويسة `x-omniroute-self-loop-key-id`، بحيث يفرض طلب الدردشة المستقبِل
سياسة الاتصالات والنماذج الخاصة بذلك المفتاح مجددًا. لا يعتمد `enforceApiKeyPolicy()`
تلك الترويسة إلا مع رمز الحامل الخاص بالحلقة الذاتية، ولذلك لا يمكنها سوى
تضييق نطاق الوصول، ويُرفض أي معرّف يتعذر تحليله.

إذا لم يكن أي نموذج رؤية مسموحًا به للمفتاح، يتنحى مسار الوصف جانبًا
ويمر الطلب دون تغيير، وهو سلوك السماح عند الفشل نفسه الخاص بضابط حماية معطّل
(البيانات الوصفية `{ skipped: true, reason: "no_permitted_vision_model" }`).
تتصرف الطلبات التي لا تحتوي على مفتاح، والمفاتيح التي لا تخضع لهذه القيود، بالطريقة نفسها تمامًا
كما كانت من قبل.

#### مطالبة الوصف المدركة للمهمة (`modalityBridgeVisionTaskAware`)

القيمة الافتراضية هي **true**. تُلحق `composeVisionPrompt()` (`visionBridgeHelpers.ts`)
نص **آخر رسالة للمستخدم** (بعد اقتطاعه إلى 500 محرف) بموجّه الوصف
الأساسي، ما يوجّه الوصف نحو ما طلبه المستخدم فعليًا
(وفق نمط codex-vision-proxy)، ويطلب من نموذج الرؤية نسخ النص الظاهر.
عند إيقاف العلامة — أو في حال عدم وجود نص للمستخدم — يُستخدم الموجّه الأساسي
دون تغيير.

يطلب طلب OpenAI المتوافق الخاص بحلقة الوصف الذاتية (`callVisionModelSingle()`
في `visionBridgeHelpers.ts`) دائمًا `image_url.detail: "high"` —
دون شروط، لكل مستدعٍ/موفّر، ومن دون الاعتماد على أي إشارة من العميل.
تؤدي المعاينة منخفضة التفاصيل إلى تدهور دقة OCR في مهمة نسخ النص تحديدًا
التي يطلبها هذا الموجّه، لذلك يطلب استدعاء الوصف نفسه دائمًا تفاصيل عالية
بصرف النظر عن مستوى التفاصيل الذي استخدمه الطلب الوارد الأصلي. يؤثر ذلك
فقط في جسم طلب الوصف الداخلي؛ ولا يغيّر كيفية تمرير OmniRoute لقيمة
`image_url.detail` الخاصة بالمستدعي في الطلب الأساسي — إذ تُطبّق تلك القيمة
الافتراضية بصورة منفصلة، ولعملاء OpenCode المكتشفين فقط، في
`defaultImageDetail()` (`open-sse/handlers/chatCore/upstreamBody.ts`). لا يحتوي
فرع تنسيق Anthropic السلكي في حلقة الوصف الذاتية على حقل `detail`، ولذلك
لا يتأثر بأي من القيمتين الافتراضيتين.

#### حد مخرجات الوصف (`modalityBridgeVisionMaxChars`)

| المفتاح                        | القيمة الافتراضية | النطاق           |
| ------------------------------ | ----------------- | ---------------- |
| `modalityBridgeVisionMaxChars` | `0`               | `0` أو 100–50000 |

تعني `0` (القيمة الافتراضية) **عدم وجود حد** — يُمرّر الوصف الذي تعيده
`callVisionModel()` دون تعديل، مع الحفاظ على السلوك الحالي.
تؤدي أي قيمة ضمن النطاق 100–50000 إلى اقتطاع الوصف مع إضافة اللاحقة
`…` قبل إدراجه مجددًا بالصيغة `[Image N]: <description>`
(`VisionBridgeGuardrail.preCall()` في `src/lib/guardrails/visionBridge.ts`).
ارفع هذه القيمة لمهام OCR كثيفة التفاصيل التي يحتاج فيها النموذج اللاحق
إلى النسخ الكامل؛ وخفّضها للحد من استهلاك الرموز مع نماذج الرؤية كثيرة
الإسهاب. يوجد حقل لوحة المعلومات ضمن لوحة Advanced في علامة تبويب Vision
(`modality-bridge-max-chars` في `ModalityBridgeVisionTab.tsx`)، ويضبط أي
قيمة بين 1 و99 صعودًا إلى الحد الأدنى 100، مع ترك القيمة الصريحة `0`
دون تغيير — إذ إن `0` قيمة Zod صالحة بحد ذاتها
(`z.union([z.literal(0), z.number().int().min(100).max(50000)])`)، وليست مجرد
قيمة افتراضية تعني «غير معيّن».

#### ذاكرة الوصف المؤقتة (`modalityBridge/bridgeCache.ts`)

ذاكرة مؤقتة داخل الذاكرة من نوع LRU + TTL لمخرجات الوصف، مشتركة على مستوى
العملية بأكملها.
المفتاح = `sha256(imageRef + composedPrompt + configuredBridgeModel)` مع
تأطير مسبوق بالطول (من دون تصادمات عند حدود الحقول). مكوّن النموذج هو نموذج
الجسر **المُهيّأ**، وليس النموذج الذي أجاب فعليًا —
فقد تلجأ `callVisionModel` داخليًا إلى نموذج احتياطي، وسيؤدي إنشاء مفتاح لكل
محاولة إلى تجزئة الذاكرة المؤقتة. لا تُخزّن عمليات الوصف الفاشلة مؤقتًا مطلقًا.
الإعدادات:

| المفتاح                         | القيمة الافتراضية | النطاق  |
| ------------------------------- | ----------------- | ------- |
| `modalityBridgeCacheEnabled`    | `true`            | —       |
| `modalityBridgeCacheTtlMinutes` | `60`              | 1–1440  |
| `modalityBridgeCacheMaxEntries` | `200`             | 10–5000 |

#### تسوية الصور البعيدة (الوصف الذاتي/جلب base64)

عندما يجلب الجسر صورة **بعيدة** بنفسه — سواء لاستدعاء الوصف الذاتي الخاص
بـ Anthropic أو لتحويل base64 بتنسيق claude السلكي
(`ensureBase64ImagesForClaudeWire`)، وكلاهما عبر
`fetchRemoteImageAsDataUri()` في `visionBridgeHelpers.ts` — يُمرّر معرّف URI
للبيانات الناتج عبر `normalizeDataUri()`
(`open-sse/utils/imageNormalize.ts`) قبل تضمينه في طلب نموذج الرؤية.
تُصغّر الصور كبيرة الحجم إلى **حافة طويلة بطول 2048px** (بما يطابق حد تغيير
الحجم الذي يطبقه OpenAI/Anthropic مسبقًا من جانب الخادم)، ما يقلل بايتات
الرفع وزمن الاستجابة من دون تغيير ما يراه نموذج الرؤية. تستخدم عملية تغيير
الحجم `sharp`، ويُحمّل عبر استيراد ديناميكي: على أي منصة يفشل فيها تحميل
ملفه الثنائي الأصلي، فإن `normalizeDataUri()` **لا تطرح أي استثناء مطلقًا** —
بل تعود إلى تمرير البايتات الأصلية كما هي، بحيث يظل مسار الوصف/تحويل base64
عاملًا دائمًا. كذلك تُمرّر البايتات غير الصورية (عندما لا تُرجع عملية الجلب
صورة قابلة لفك الترميز) دون تغيير. تقتصر هذه التسوية على الصور التي يجلبها
الجسر لاستدعائه الذاتي — ولا تُطبّق مطلقًا على حمولة التمرير الخام الخاصة
بالمستدعي، بما يتوافق مع مبدأ عدم التعديل إلا عند الاشتراك الصريح
(Hard Rule #20).

#### مخطط الإعدادات + الترحيل

تخضع مفاتيح `modalityBridge*` الجديدة للتحقق بواسطة Zod في
`updateSettingsSchema`
(`src/shared/validation/settingsSchemas.ts`): `modalityBridgeVisionEnabled`،
`modalityBridgeVisionMode`، `modalityBridgeVisionModel`،
`modalityBridgeVisionTaskAware`، `modalityBridgeVisionPrompt`،
`modalityBridgeVisionTimeout`، `modalityBridgeVisionMaxImages`،
`modalityBridgeVisionMaxChars`، وثلاثية `modalityBridgeCache*`، ومجموعة
`modalityBridgeAudio*` التي يستخدمها Audio Bridge. ينسخ الترحيل
`141_modality_bridge_settings.sql` قيم `visionBridge*` القديمة الحالية إلى
المفاتيح الجديدة المطابقة (عملية متكررة آمنة، ولا تستبدل مطلقًا قيمة
`modalityBridge*` عيّنها المشغّل)؛ وتظل المفاتيح القديمة مقبولة كخيار
احتياطي للقراءة خلال دورة إصدار واحدة.

#### ترويسة الشفافية + الإحصاءات

تحمل الاستجابات المحوّلة عبر الوصف
`x-omniroute-modality-bridge: image->text;model=<visionModel>;parts=<n>`
(تُنشأ بواسطة `buildModalityBridgeHeader()` في
`modalityBridge/bridgeStats.ts`، وتُضاف بواسطة
`withModalityBridgeHeader()` في `src/sse/handlers/chatHelpers.ts`).
لا تحصل الطلبات المعاد توجيهها على **أي** ترويسة — إذ لم تتغير الحمولة،
كما أن تبديل النموذج ظاهر بالفعل في حقل `model` داخل جسم الاستجابة.

يعيد `GET /api/modality-bridge/stats` (مصادقة الإدارة، بالمستوى نفسه الخاص بـ
`GET /api/settings`) عدّادات كل نمط المخزّنة في الذاكرة
`{ attempts, successes, bridged, cacheHits, failures, totalLatencyMs,
latencySamples, averageLatencyMs, lastUsedAt }` لكل من `vision` و`audio` و
`video`. يستخدم `averageLatencyMs` قيمة `latencySamples` مقامًا، وليس جميع
المحاولات؛ ولا تنشئ العملية التي لا تحتوي على قياس زمني عينة وهمية مدتها صفر
مللي ثانية. يظل `bridged` الاسم المستعار المتوافق مع الإصدارات السابقة لعمليات
التحويل الناجحة؛ ولا تؤدي المحاولات الفاشلة إلى زيادته.
تُصفَّر العدّادات عند إعادة تشغيل العملية حسب التصميم
(قياس عن بُعد، وليس محاسبة).

#### إعداد لوحة المعلومات

صفحة لوحة المعلومات المخصصة هي
`/dashboard/settings/modality-bridge`. تحافظ علامات التبويب `Vision` و`Audio`
و`Video`، التي يمكن الوصول إليها عبر عنوان URL، على معاملات الاستعلام عند تبديل
قيمة `tab`.
تعرض علامة التبويب Vision التمكين والوضع واختيار النموذج (بما في ذلك الإعداد
الافتراضي التلقائي) وصياغة المطالبات المدركة للمهمة، وحدود المهلة/الصورة/طول
الوصف/ذاكرة التخزين المؤقت المتقدمة، وعدّادات وقت التشغيل، وطلبًا نموذجيًا
محميًا. علامة التبويب Audio فعّالة أيضًا: فهي تعرض التمكين، ومنتقي نماذج خاصًا
بـ STT فقط يتضمن Auto، وحدود المهلة/المدة القصوى للمقطع، وعدّادات الصوت، واختبار
عينة `input_audio`. علامة التبويب Video وظيفية: فهي تعرض حالة وقت تشغيل
FFmpeg/ffprobe — وهي واحدة من أربع حالات صريحة في واجهة المستخدم (`unknown`
بينما يكون الفحص قيد التنفيذ أو يتعذر إكماله، و`restricted` على مضيف لوحة
معلومات غير تابع للواجهة الاسترجاعية حيث يتم تخطي الفحص من جانب العميل،
و`unavailable` بعد إجراء الفحص والتأكد من عدم التوفر، أو `available` مع إصداري
FFmpeg/ffprobe) — وتحفظ حدود التمكين/النموذج/الإطارات/الفيديو/المهلة، وترشّح
منتقي النماذج ليقتصر على النماذج الداعمة للرؤية، وتعرض عدّادات الفيديو.

أصبحت بطاقة Vision Bridge السابقة ضمن إعدادات الذكاء الاصطناعي رابط توافق إلى
الصفحة الجديدة؛ ولم تعد تمتلك نسخة ثانية من النموذج. يربط Media Providers
أيضًا مساري عمل Image-to-Text وSpeech-to-Text بعلامتي تبويب Modality Bridge
المقابلتين دون إزالة بيئة اختبار Speech-to-Text الحالية.

**تجاوز قبول الحلقة الذاتية:** عندما يُوجَّه استدعاء الوصف عبر الحلقة الذاتية
`/v1` الخاصة بـ OmniRoute (نموذج موفّر غير قياسي)، يرسل الطلب الفرعي
`x-omniroute-admission-bypass: internal` وتتم مصادقته باستخدام بيانات اعتماد
الحلقة الذاتية التي تم حلّها — القيمة الحارسة المحلية `sk_omniroute` في الوضع
المحلي، أو مفتاح البيئة `OMNIROUTE_API_KEY` / `ROUTER_API_KEY` الذي يضبطه
المشغّل (#1350)، بحيث تظل عمليات النشر التي تستخدم `REQUIRE_API_KEY=true`
قادرة على تنفيذ استدعاء الوصف. لا يُقبل التجاوز إلا لبيانات الاعتماد المطابقة
تمامًا، ولذلك لا يمكن للعملاء الخارجيين استخدام الترويسة لتخطي القبول.

توجد الإعدادات الافتراضية القديمة في
`src/shared/constants/visionBridgeDefaults.ts`؛ بينما توجد الإعدادات الافتراضية
الجديدة للوضع/الإدراك بالمهمة/ذاكرة التخزين المؤقت، إلى جانب محلّل الإعدادات،
في `src/shared/constants/modalityBridgeDefaults.ts`. يوفّر حاجز الحماية خيار
منشئ باسم `deps` حتى تتمكن الاختبارات من حقن تنفيذات وهمية لـ `getSettings`
و`callVisionModel`.

### جسر الصوت (`audioBridge.ts`) — Modality Bridge PR-3

يعترض طلبات المحادثة التي تحتوي على صوت قبل وصولها إلى هدف غير معروف بقبوله
إدخالًا صوتيًا. ولا يعيد توجيه طلب المحادثة مطلقًا: تُنسخ الأجزاء الصوتية نصيًا
من خلال نقطة النهاية الحالية متعددة الأجزاء والمتوافقة مع OpenAI، ثم يتابع
نموذج المحادثة المختار باستخدام النصوص المنسوخة.

التدفق:

1. حلّ `supportsAudio` من خلال `getResolvedModelCapabilities()`. تكون الأولوية
   لبيانات التعريف الصريحة في سجل الموفّرين، ثم بيانات النموذج الثابتة، ثم
   `modalities_input` المتزامنة. تكون قائمة الإدخال المعلنة التي لا تحتوي على
   `audio` مساوية لـ `false`؛ وعند عدم وجود أي دليل على القدرة تظل القيمة
   `null`. تعمل القيمتان `false` و`null` كلتاهما على تنشيط الجسر المحافظ، بينما
   تؤدي `true` إلى تجاوزه.
2. حلّ إعدادات `modalityBridgeAudio*` واستخراج أجزاء الصوت القابلة للوصل من
   المستوى الأعلى من كل رسالة عبر الكاشف المشترك `detectMediaParts()`. أشكال
   النقل المدعومة هي `input_audio` و`audio_url` في OpenAI، و
   `source.media_type: "audio/*"`. يُكتشف الصوت المتداخل لأغراض التوجيه، لكنه
   لا يُزال بواسطة مسار الوصل. يُحدّ العمل بواسطة
   `modalityBridgeAudioMaxClips`؛ وتظل الأجزاء اللاحقة دون تغيير.
3. الالتزام بقيمة `provider/model` مهيأة، أو السماح لـ
   `selectAudioBridgeModel()` باستعراض `AUDIO_TRANSCRIPTION_PROVIDERS` وفق
   ترتيب الكتالوج الثابت واختيار أول نموذج يمتلك بيانات اعتماد موفّر نشطة
   وقابلة للاستخدام.
4. تحوّل `callAudioTranscription()` الصوت بترميز base64/معرّف URI للبيانات إلى
   `file` متعدد الأجزاء، أو تنزّل `audio_url` بعيدًا عبر حارس الاتصالات الصادرة
   العامة فقط مع تثبيت DNS وحد أقصى يبلغ 25 ميغابايت. ثم ترسل الملف والنموذج
   المحدد عبر POST إلى الحلقة الذاتية المحلية `/v1/audio/transcriptions`، مع
   المصادقة باستخدام `resolveSelfLoopBearer()`. ينفّذ مسار النسخ الحالي البحث
   المعتاد عن بيانات الاعتماد، ومعالجة فترات التهدئة/حدود المعدل، والتوجيه إلى
   الموفّر.
5. تستبدل الاستدعاءات الناجحة أجزاءها بـ `[Audio N]: <transcript>`. تعمل
   الاستدعاءات باستخدام `Promise.allSettled`: يحافظ فشل منفرد على جزء الصوت
   الأصلي ذاك (عقد #4012). إذا فشلت جميع الاستدعاءات وثبت أن الهدف
   `supportsAudio === false`، تصبح الأجزاء
   `[Audio N]: (unavailable — no STT provider connected)` (عقد #8430). بالنسبة
   إلى هدف غير معروف (`null`)، تظل النتيجة دون تغيير عند فشل جميع الاستدعاءات.
   ويتلقى الهدف الذي ثبت أنه نصي فقط ولا يملك بيانات اعتماد STT قابلة
   للاستخدام العنصر النائب الصريح نفسه دون إصدار استدعاء شبكة.

تستخدم النصوص المنسوخة بنجاح ذاكرة التخزين المؤقت LRU/TTL الخاصة بـ Modality
Bridge على مستوى العملية. يجمع المفتاح بين مرجع الصوت وتسمية العملية الثابتة
`audio-transcription` ونموذج STT المحدد؛ ولا تُخزَّن حالات الفشل مؤقتًا مطلقًا.
تُحدّث محاولات الصوت العدّادات المشتركة `bridged` و`cacheHits` و`failures`
و`lastUsedAt`.
تحمل الاستجابات المحوّلة
`x-omniroute-modality-bridge: audio->text;model=<sttModel>;parts=<n>`؛ ولا تتلقى
الطلبات التي لم تتغير مقطعًا من Audio Bridge.

تكون إعدادات وقت التشغيل مدعومة بقاعدة البيانات ويجري التحقق منها باستخدام Zod:

| المفتاح                       | القيمة الافتراضية | النطاق              |
| ----------------------------- | ----------------- | ------------------- |
| `modalityBridgeAudioEnabled`  | `true`            | —                   |
| `modalityBridgeAudioModel`    | `""`              | تلقائي أو معرّف STT |
| `modalityBridgeAudioTimeout`  | `60000`           | 1000–300000         |
| `modalityBridgeAudioMaxClips` | `3`               | 1–10                |

تظل ذاكرة التخزين المؤقت المشتركة خاضعة للتحكم بواسطة `modalityBridgeCacheEnabled`،
و`modalityBridgeCacheTtlMinutes`، و`modalityBridgeCacheMaxEntries`.

### جسر الفيديو (`videoBridge.ts`، `videoBridgePipeline.ts`)

يعترض أجزاء الفيديو ذات المستوى الأعلى في `messages` الخاصة بـ Chat Completions وفي
`input` الخاصة بواجهة Responses API، وذلك قبل استدعاء وجهة لا يُعرف عنها دعم الفيديو
أصليًا. الأشكال المدعومة هي `input_video`، و`video_url`، و`video_source`، وعناوين URL
بروتوكول HTTPS، ومعرّفات URI للبيانات بصيغة `data:video/*;base64,...`. لا تُعامل أسماء
الملفات المجردة في النص على أنها فيديو.

يتولى `VideoBridgeGuardrail.preCall` (`videoBridge.ts`) اجتياز الطلب، والتحقق من
الإمكانات/السياسة، والتجميع لكل طلب، وحمولة الاستجابة. أما العمل الخاص بكل فيديو —
وهو الحصول عليه، وذاكرة التخزين المؤقت للنتيجة الكاملة، ووصف تسلسل الإطارات
(الذي يدمج أي نص صوتي يصرّح به المستدعي)، ومقاييس/إلغاء/تنظيف كل محاولة — فهو مخفي
خلف `processVideoPart` في `videoBridgePipeline.ts`، والذي يُستدعى مرة واحدة لكل جزء
فيديو داخل حلقة `preCall`. وتعرّف تلك الوحدة أيضًا حدود المنافذ الصريحة
`VideoMediaBrokerPort` (الحصول على البايتات واستخراج الإطارات المأخوذة كعينات)،
و`VideoAudioTranscriptionPort` (دمج نص صوتي يصرّح به المستدعي مع التسميات التوضيحية
للعيّنات)، و`VideoDrilldownPort` (حد استمرارية بيانات التعمق في الإطارات؛ لم يُوصّل
بعد بـ `processVideoPart` — إذ لا يكتب إدخالات التعمق حاليًا سوى مسار
`/api/modality-bridge/video/drilldown` المنفصل).

لا يستورد مسار طلبات `/v1` العام أي عملية فرعية ولا يستدعيها مطلقًا. تُنزّل مقاطع
الفيديو البعيدة ضمن حد يبلغ 50 MiB؛ وتخضع مقاطع فيديو base64 المضمّنة لحد أقصى
تحفظي يبلغ 36 MiB من البيانات المفكوكة لكل فيديو، كي يظل غلاف
النموذج/الرسائل/التأطير ضمن حد قبول طلبات JSON العامة البالغ 50 MiB. يُتحقق من
الطول المضمّن وتقديرات الحجم بعد فك الترميز قبل التخصيص. يُشترط HTTPS في عنوان URL
البعيد الأولي وفي كل عملية إعادة توجيه، باستخدام آلية الحماية الحالية للاتصالات
الصادرة العامة فقط مع تثبيت DNS. ثم تعبر البايتات حد وسيط الخدمة الداخلي الدقيق
`POST /api/modality-bridge/video/extract`. هذا المسار موسوم بكل من `LOCAL_ONLY`
و`SPAWN_CAPABLE`، ولا يقبل إلا طلبًا موثّقًا لكل عملية وقادمًا من واجهة loopback
موثوقة، ولا يقبل مطلقًا عنوان URL أو مسار نظام ملفات أو ملفًا تنفيذيًا أو قائمة
وسائط. يفرض مسار حجم نص API وقارئ النص التزايدي الخاص بالمعالج، كلٌ على حدة، حدًا
أقصى لمدخلات الوسيط يبلغ 50 MiB. تعالج قائمته المحدودة عملية استخراج واحدة في كل
مرة، وتسمح بأربع مهام معلّقة، وتضع حدًا أقصى للمدخلات المعلّقة يبلغ 100 MiB.

داخل الوسيط، يقرأ `ffprobe` ملفًا محليًا خاصًا؛ وتستبعد قائمة السماح الثابتة
للتنسيقات تنسيقات قوائم التشغيل وملفات البيان. بالنسبة إلى حاويات عائلة MOV
المسموح بها، تظل مراجع بيانات MOV الخارجية معطلة افتراضيًا، ولا يفعّلها الأمر
الثابت. يستخدم كل من `ffprobe` و`ffmpeg` قائمة سماح بروتوكولات تقتصر على `file`،
وخيطًا واحدًا، ومصفوفات وسائط ثابتة، ومن دون shell، مع حلّ الملفات التنفيذية من
`PATH`. لا تُعد تدفقات صور الغلاف المرفقة مرشحة قابلة للتشغيل. يجب أن تستوفي جميع
التدفقات القابلة للتشغيل الحدود، ويُفضّل تدفق افتراضي صريح قبل الرجوع الحتمي إلى
أقل فهرس. تقتصر مدة مقاطع الفيديو على 600 ثانية، و8,192 بكسل لكل بُعد،
و33,554,432 بكسل للمصدر. يأخذ FFmpeg من 1 إلى 16 إطار JPEG عند نقاط المنتصف،
ويصغّر الحافة الطويلة إلى 1,024 بكسل كحد أقصى دون تكبير المدخلات الأصغر، ولا يتلقى
عنوان URL مطلقًا. تكون سياسة أخذ العينات `uniform` افتراضيًا. تنفّذ سياستا
`scene_aware` الاختيارية و`segment_aware` التجريبية تمريرة FFmpeg ثابتة إضافية
واحدة على التدفق المحلي الذي سبق التحقق منه، وتحددان طوابع زمنية محدودة للمشاهد
عبر `showinfo`، وتعودان بصورة حتمية إلى نقاط المنتصف الموحدة نفسها عند فشل
الكاشف، أو انتهاء المهلة، أو وجود مخرجات مشوهة، أو فراغ مجموعة المرشحين. يوزع وضع
الوعي بالمقاطع عينات نقاط المنتصف بالتناسب مع فواصل المشاهد التي تم التحقق منها؛
وترد أدناه تفاصيل أدلة الوعي بالمقاطع وسلوك الرجوع. يُطبّق الحد الأقصى الصارم
البالغ 16 إطارًا بعد الاختيار في كل سياسة. عندما تكون ميزانية طلب واعٍ بالمشاهد
إطارًا واحدًا فقط، فإنه يستخدم نقطة المنتصف الموحدة لنافذة الفيديو الكاملة النشطة
أو نافذة التركيز، ويبلّغ عن `policyEffective: uniform`: إذ لا يمكن لإطار مشهد واحد
محدد الحفاظ على طرفي النطاق الزمني. يمكن للمستدعي اختياريًا توفير نافذة تركيز
محدودة (`start`/`end` بالثواني)؛ وتُقيّد الحدود بمدة الوسائط، وتُرفض النوافذ
المعكوسة أو غير المحدودة، وتُنفّذ جميع سياسات أخذ العينات داخل الفاصل المطبّع فقط.
تُضمّن النافذة الناتجة في بيانات أخذ العينات الوصفية وفي بادئة الوصف غير الموثوق،
كي تتمكن النماذج اللاحقة من تمييز مقتطف مركّز عن الخط الزمني الكامل.

يمثل التركيز الدلالي للتسميات التوضيحية إعدادًا منفصلًا وصريحًا. يحافظ وضع التحليل
الافتراضي `full` على موجّه الإطارات الحالي ولا يمرر نص الطلب إلى نموذج التسميات
التوضيحية مطلقًا. في وضع `focused`، لا يقرأ الجسر سوى أحدث `text`/`input_text`
غير فارغ أنشأه المستخدم من حاوية Chat أو Responses نفسها، ويطبّعه إلى NFC، ويطوي
محارف التحكم والمسافات البيضاء، ويقصره على 500 نقطة ترميز Unicode. تؤدي النتيجة
الفارغة إلى الرجوع إلى موجّه `full` نفسه تمامًا. يُسلسل التلميح القابل للاستخدام
بصيغة JSON داخل كتلة مخصصة لسياق مستخدم غير موثوق، ولا يجوز له إلا إعطاء الأولوية
للتفاصيل القابلة للملاحظة؛ ولا يمكنه تجاوز التحذير المنفصل من اتباع التعليمات
المرئية أو المسموعة في الوسائط. لا يستنتج التركيز النصي `start`/`end` مطلقًا ولا
يغير آخذ العينات الزمني.

#### دليل المقاطع البنيوي FU-07

يستخدم `segment_aware` تمريرة تحليل مسبق واحدة محدودة على دفق الفيديو المحلي الذي تم التحقق منه مسبقًا. تقوم سلسلة المرشحات الثابتة أولًا بالتحجيم إلى عرض لا يتجاوز 320 بكسلًا، وتكتشف تغيّرات المشاهد والفواصل المتجمدة، ثم تأخذ عينة بمعدل إطار واحد في الثانية لقياس الضبابية، ومتوسط النصوع، والمعلومات المكانية/الزمنية. تقتصر التمريرة على 600 عينة بنيوية، وخيط FFmpeg/مرشح واحد، وقوائم السماح نفسها الخاصة ببروتوكول `file` فقط والحاويات، وحد أقصى قدره 1 MiB لمخرجات العملية، وما لا يزيد على 30 ثانية ضمن الإلغاء/المهلة النهائية المشتركة للوسيط. ولا تقبل مطلقًا أمرًا أو مرشحًا أو مسارًا أو عنوان URL من الطلب.

تمثل القيم البنيوية أدلة أخذ عينات حتمية، وليست فهمًا دلاليًا للفيديو. فهي لا تستنتج الموضوعات أو الأفعال أو التسميات التوضيحية أو الكلام أو نية المستخدم. تشكّل حدود المشاهد والتجمد مقاطع؛ ولا تؤثر تغطية التجمد والضبابية والتعريض والتفاصيل المكانية والتغير الزمني إلا في كيفية تخصيص ميزانية الإطارات الحالية البالغة 1–16 إطارًا. يُقيّد المقطع المتجمد بالكامل بإطار واحد، بينما تتنافس المقاطع غير المتجمدة على الميزانية المتبقية. عندما يفوق عدد الحدود عدد الإطارات، يُحتفظ بتغطية موحدة للخط الزمني كي لا تتمكن القطوع المبكرة السريعة من إخفاء مقطع نهائي طويل. وتُدمج حدود المشاهد الواقعة ضمن دقة التحليل البالغة ثانية واحدة من حد تجمد.

يؤدي غياب المرشحات، أو الأدلة المشوهة/الفارغة، أو خطأ الكاشف، أو انتهاء مهلة التحليل المسبق المحدود إلى الرجوع المتسامح إلى سياسة نقاط المنتصف الموحدة نفسها تمامًا. أما إلغاء المتصل أو بلوغ المهلة النهائية للوسيط فلا يؤديان إلى الرجوع المتسامح: بل ينهيان العملية الفرعية قيد التنفيذ، ويمنعان استخراج الإطارات لاحقًا، وتُزال شجرة الملفات المؤقتة الخاصة في `finally`.

ينشئ `scripts/perf/video-bridge-fu07-eval.ts` تجهيزات FFmpeg حقيقية وحتمية لقياس وفورات استدعاءات التسميات التوضيحية بعد إزالة التكرار، وتخصيص الميزانية للحركة الكثيفة، وأدلة الضبابية/التعريض/SI-TI، والقطوع السريعة ذات النهاية الطويلة، والنتائج الإيجابية الكاذبة للتلاشي التدريجي. ويسجل زمن التحليل المسبق الفعلي، وكذلك وقت CPU للعملية الفرعية وذروة RSS عند توفر `/usr/bin/time`. فحوصات الجودة فيه ليست سوى مراجع بنيوية. تظل جودة نموذج التسميات التوضيحية الحقيقي `HOLD` لأن أداة الاختبار هذه لا تحتوي على نقطة نهاية مصرّح بها أو مُقيِّم ثابت. كما تظل الوفورات المالية `HOLD` ما لم يوفر `--caption-cost-per-call-usd` تقديرًا صريحًا وموجبًا للتكلفة لكل استدعاء؛ ولا يختلق البرنامج النصي أيًا من النتيجتين مطلقًا.

يقتصر كل إطار على 4 MiB، ويقتصر مجموع كل الإطارات الخام على 23 MiB، وتقتصر استجابة الوسيط المتسلسلة على 32 MiB. ويُزال دليل مؤقت خاص في `finally`. لا يضمّن OmniRoute برنامج FFmpeg ولا يقبل مسارًا مخصصًا للملف التنفيذي. قبل إنشاء التسميات التوضيحية، يطبق الجسر تمريرة محافظة لإزالة التكرار المرئي: يُختزل كل ملف JPEG إلى مخزن مؤقت بتدرج رمادي بحجم 16×16، ولا يُقارن إلا بآخر إطار تم الاحتفاظ به. عندما تتجاوز ميزانية التسميات التوضيحية المطلوبة إطارًا واحدًا، يوفر الاستخراج مجموعة مرشحين محدودة لا تتجاوز ضعفي تلك الميزانية ولا تزيد مطلقًا على 16 إطارًا. لا يُطبّق الحد الأقصى المطلوب إلا بعد إزالة التكرار، مع الحفاظ على أول وآخر مرشح محدد أثناء التخفيف النهائي عندما تكون الميزانية إطارين على الأقل. تستخدم سياسة
`grayscale-16x16-mean-cells-v2` ذات الإصدار المحدد القيمة الأكبر بين متوسط فرق النصوع ونسبة خلايا الصورة المصغرة التي يبلغ فرقها المعياري 0.05 على الأقل. حد التكرار هو الثابت 0.04، وقد اختير لقابلية التنبؤ بدلًا من إتاحته كإعداد في وقت التشغيل. تحافظ إشارة التباين العالي الثانوية هذه على الحركة الصغيرة وتغيّرات النص المرئي التي قد تخفيها مقارنة تعتمد على المتوسط وحده. تؤدي أخطاء المقارن أو مفكك الترميز إلى الرجوع المتسامح والحفاظ على التغطية. تفصل بيانات المخرجات الوصفية بين المرشحين المستخرجين، والإطارات التي استُخدمت بنجاح، والنسخ المرئية المكررة التي أُسقطت.

يمكن لجزء فيديو معلَّم صراحةً أن يطلب لوحة اتصال ذات طوابع زمنية. ينشئ الجسر شبكة JPEG لا تتجاوز 4 أعمدة و16 إطارًا. تدمج كل خلية بحجم 512 بكسلًا الطابع الزمني لمصدرها داخل شريط سفلي عالي التباين، بينما تظل الطوابع الزمنية نفسها موجودة في البيانات الوصفية النصية للربط والتدقيق في المراحل اللاحقة. يظل ملف JPEG الكامل محدودًا بـ 32 MiB. إذا تعذر على `sharp` فك ترميز الشبكة أو تركيبها، يرجع الجسر إلى إطارات JPEG الفردية؛ ويظل إلغاء العميل منتشرًا عبر عملية اللوحة.

تُفصل أدلة الترقية عمدًا عن الاختبار المصغر التركيبي للتركيب. يعرّف `scripts/perf/video-bridge-contact-sheet-eval.ts` أداة اختبار A/B ذات مخطط محدد الإصدار لنماذج الرؤية الحقيقية المتوافقة مع OpenAI. وهي تقيس الرموز التي يبلغ عنها المزوّد، وزمن الاستجابة الفعلي من البداية إلى النهاية (بما في ذلك تركيب اللوحة)، وعدد استدعاءات النموذج، والاحتفاظ بالحقائق المحددة في البيان. لا تُكتب استجابات النموذج الخام في التقرير؛ بل يُحتفظ فقط بملخصات SHA-256 ومعرّفات الحقائق المطابقة. لا تجري أداة الاختبار أي اتصال بالشبكة أو استدعاء مدفوعًا للنموذج ما لم يُمرر `--execute-real` وتتم تهيئة `--model` و`OMNIROUTE_BASE_URL` و`OMNIROUTE_API_KEY`. من دون ذلك التشغيل الحقيقي الصريح، يظل حكمها القابل للقراءة آليًا `HOLD`؛ ولا تُعد قياسات الحمولة الاصطناعية/عدد الاستدعاءات وحدها دليلًا على الترقية.

يمكن للمتصلين إرفاق مصفوفة `transcript.cues` اختيارية بجزء فيديو مدعوم عندما يمتلكون مسبقًا نصًا متزامنًا. يجب أن يحمل كل تلميح `text`، وفاصلًا زمنيًا محدودًا `start`/`end` يقع ضمن المدة المستطلعة، و`source` مدرجًا في قائمة السماح (`client` أو `embedded` أو `audio-bridge`)؛ تكون القيمة الافتراضية لـ`confidence` هي `1` ويجب أن تبقى بين `0` و`1`. تُدمج التلميحات المتطابقة تمامًا. لا يبدأ OmniRoute مطلقًا عملية نسخ صوتي استنادًا إلى هذه البيانات الوصفية: تُنسخ التلميحات المتحقق منها إلى النتيجة الموصوفة مع المصدر والثقة والفاصل الزمني، وتُعرض كملاحظات غير موثوق بها إلى جانب تسميات الإطارات التوضيحية. يُرفض النص غير الصالح، أو الواقع خارج النطاق، أو الخالي من معلومات المنشأ بدلًا من مزجه في دفق التسميات التوضيحية. حقل `source` معلن حاليًا من جانب المتصل، ولا يتحقق منه الخادم: يفرض OmniRoute أن تكون القيمة إحدى السلاسل الثلاث المسموح بها، لكنه لا يؤكد بعد تشفيريًا أن تسمية `embedded` أو `audio-bridge` جاءت فعلًا من عملية استخراج يملكها الخادم. تعامل مع `source` باعتباره تلميحًا غير موثوق به إلى أن يُنفذ ذلك التحقق؛ ولا تبنِ عليه قرارات التفويض.

ذاكرة التخزين المؤقت المضغوطة القياسية والمحدودة. يتضمن حد نقل JSON الحمل الإضافي لـ Base64 لسقف
الإدخال مفكوك الترميز البالغ 32 MiB. ويسجّل كل
اشتقاق مخزّن صيغة JPEG ودقتها بعد التحقق منهما، وسياسة أخذ العينات،
وإصدار الاشتقاق، ووقت الإنشاء، وتجزئة المحتوى المحسوبة على الخادم، ومرجع
الأصل المُجزّأ، إضافةً إلى تجزئة محتوى الأصل المقدمة من المستدعي الموثوق.
ويُتحقق من الإلغاء بين مراحل فك الترميز/التجزئة غير المتزامنة وقبل الالتزام الذري
بذاكرة التخزين المؤقت.

لا توصل هذه الدفعة بعدُ منتِجًا للإنتاج بالمسار، ولا
توفر اختيار متغيرات متعددة الدقة. ولذلك، لا يضيف مسار طلب Video Bridge
الشفاف أي عمل، بينما يظل اشتقاق الهوية الأساسية المرتبطة بالمستأجر
ودورة حياة FU-08 الكاملة متعددة الدقة أعمال متابعة صريحة
بدلًا من توثيقها كسلوك مكتمل.

تُنشأ تسميات توضيحية للإطارات بالتتابع باستخدام نموذج Video المُهيأ. ويرث تجاوز
Video الفارغ إعداد Vision؛ وإذا كان كلاهما فارغًا، يختار
الموجّه التلقائي لـ Vision النموذج الفعلي القادر على معالجة الرؤية. تستبدل التسميات التوضيحية
الناجحة الجزء الأصلي ببادئة ثابتة `[Video description:` تشير أيضًا
إلى أن النص ملاحظة غير موثوقة مشتقة من الوسائط، وتطلب من النماذج اللاحقة
عدم اتباع التعليمات الموجودة في الوسائط. تتضمن مفاتيح ذاكرة التخزين المؤقت لتسميات الإطارات
بايتات JPEG، والموجّه، والطابع الزمني، والنموذج الفعلي؛ ولا تُخزّن مؤقتًا سوى
التسميات التوضيحية الناجحة. تحتفظ إدخالات ذاكرة التخزين المؤقت بنموذج المُنتِج الفعلي الناجح،
بما في ذلك نموذج احتياطي؛ ويبلغ الجسر عن `mixed` عندما تكون الإطارات المختلفة
قد أُنتجت بواسطة نماذج مختلفة. تعيد إصابة ذاكرة التخزين المؤقت استخدام هوية ذلك المُنتِج
بدلًا من إعادة تسميتها على أنها خطة التوجيه المطلوبة. ويُربط مفتاح ذاكرة التخزين المؤقت لنتيجة
الفيديو بالكامل بكل مُدخل يغير الناتج — الموجّه، والنموذج الفعلي،
وسياسة أخذ العينات، وعدد الإطارات، ووضع التحليل الدلالي، وبصمة SHA-256
لتلميح التركيز بعد تطبيعه، ونافذة التركيز، و`transcript`،
و`audioTranscript`، وعلامة ورقة جهات الاتصال — ولذلك يؤدي تغيير أي من تلك
الأبعاد إلى فقدان في ذاكرة التخزين المؤقت، وليس إعادة استخدام بيانات قديمة مطلقًا. كما أن إصدار
سياسة إزالة التكرار المرئي، وعتبتها، والعدد المحدود من الإطارات المرشحة مذكورة صراحةً في
مفتاح ذاكرة التخزين المؤقت للنتائج وبياناتها الوصفية؛ ولذلك لا يمكن لتغيير السياسة إعادة استخدام
وصف قديم للفيديو بالكامل. تحتفظ البيانات الوصفية لذاكرة التخزين المؤقت للنتائج v4 بالوضع
والبصمة، ولا تحتفظ أبدًا بمهمة المستخدم الخام. وتبلغ البيانات الوصفية لحاجز الحماية عن وضعي
التحليل المطلوب والفعلي معًا؛ ويُبلّغ عن وضع `focused` مطلوب دون
نص مستخدم قابل للاستخدام باعتباره `full` فعليًا.

يستخرج حاجز الحماية كل جزء فيديو مدعوم، لكنه لا يصف أكثر من
`modalityBridgeVideoMaxVideos`. وبالنسبة إلى هدف ثبت أن لديه
`supportsVideo === false`، تتحول مقاطع الفيديو الفاشلة والتي تتجاوز الحد إلى علامات نصية آمنة
صريحة، بحيث لا يبقى أي فيديو خام. وعندما تكون القدرة مجهولة، تظل تلك الأجزاء
دون تغيير. وتتجاوز الأهداف التي لديها `supportsVideo === true` الجسر.
تنتشر إشارة إلغاء طلب العميل عبر التنزيل، وطابور الوسيط،
والعمليات الفرعية، واستدعاءات إنشاء التسميات التوضيحية؛ وتوقف عمليات الإلغاء المعالجة بين مقاطع الفيديو
ولا تفشل أبدًا بصورة تسمح بمرور الوسائط الخام.

إعدادات وقت التشغيل مدعومة بقاعدة البيانات ويجري التحقق منها باستخدام Zod:

| المفتاح                             | القيمة الافتراضية | النطاق / السلوك                                                                                       |
| ----------------------------------- | ----------------- | ----------------------------------------------------------------------------------------------------- |
| `modalityBridgeVideoEnabled`        | `false`           | وقت تشغيل اختياري، يتطلب الاشتراك                                                                     |
| `modalityBridgeVideoAnalysisMode`   | `"full"`          | يحافظ `full` على التسميات التوضيحية العامة؛ ويستخدم `focused` سياق أحدث مستخدم، محدودًا وغير موثوق به |
| `modalityBridgeVideoModel`          | `""`              | يرث نموذج Vision Bridge                                                                               |
| `modalityBridgeVideoFrameCount`     | `8`               | 1–16                                                                                                  |
| `modalityBridgeVideoSamplingPolicy` | `"uniform"`       | `uniform` أو `scene_aware` أو `segment_aware` التناسبي؛ ويؤدي فشل الكاشف إلى الرجوع إلى `uniform`     |
| `modalityBridgeVideoMaxVideos`      | `1`               | 1–4                                                                                                   |
| `modalityBridgeVideoTimeout`        | `120000`          | 1000–120000 ms                                                                                        |

تُقيَّد قيم مهلة Video القديمة والمخزنة التي تتجاوز 120 ثانية عند
الموعد النهائي للوسيط؛ وتُرفض عمليات كتابة الإعدادات الجديدة التي تتجاوز ذلك الحد.
يتطلب `GET /api/modality-bridge/video/runtime` محلية loopback موثوقة ومختومة
قبل المصادقة أو فحص وقت التشغيل، ثم يتطلب مصادقة إدارية.
ولا يعيد سوى `available`، وإصدارات FFmpeg/ffprobe المنقّحة، وسبب ثابت
عندما يكون وقت التشغيل غير متاح. نقطة نهاية الاستخراج الداخلية ليست
واجهة API عامة للرفع: يعيد تشبع الطابور `503` مع `Retry-After`، ويعيد
انقطاع اتصال المستدعي `499`، ويعيد الموعد النهائي الثابت للوسيط `504`. تضيف الاستجابات المحوّلة
`video->text;model=<visionModel>;parts=<videos>` إلى ترويسة
`x-omniroute-modality-bridge` المركزية دون إزالة مقاطع Vision أو Audio.

### أداة إخفاء معلومات التعريف الشخصية (`piiMasker.ts`)

تعمل في **كلتا** المرحلتين.

- يقوم **`preCall`** باستنساخ الحمولة، ويمرّ عبر `system` و`messages` و`input` و
  `prompt` (بما في ذلك عناصر السلاسل النصية العادية)، ويطبّق `processPII()` (من
  `@/shared/utils/inputSanitizer`) على حقول `content`/`text` النصية. عندما تكون
  `PII_REDACTION_ENABLED=true`، تُحجب معلومات تحديد الهوية الشخصية المكتشفة في
  الحمولة الصادرة. وهذا مستقل عن `INPUT_SANITIZER_MODE` (الذي يتحكم فقط في
  سياسة حقن المطالبات). عندما يكون الحجب معطّلًا، تسجّل الاستدعاء أعداد
  حالات الاكتشاف من دون إعادة كتابة المحتوى.
- يقوم **`postCall`** باستنساخ الاستجابة استنساخًا عميقًا، ويشغّل `sanitizePIIResponse()` بالإضافة إلى
  أداة إخفاء بنية Responses API (`maskResponsesOutput` — التي تغطي
  `output_text` و`output[].content[].text`). إذا حدث أي حجب، فإن
  الاستجابة المعدّلة تحل محل الأصلية.

لا يمنع حاجز الحماية أي طلب مطلقًا؛ بل يضيف تعليقات توضيحية فقط (`meta.detections`،
`meta.redacted`) أو يعيد الكتابة.

### حقن المطالبات (`promptInjection.ts`)

يكتشف البنى العدائية في المحتوى المقدّم من المستخدم ويفرض
السياسة المضبوطة. يتحدد السلوك بواسطة متغيرات البيئة وخيارات
المُنشئ:

| الإعداد  | متغير البيئة                                                                                               | القيمة الافتراضية | التأثير                                                                                                                                                                                                 |
| -------- | ---------------------------------------------------------------------------------------------------------- | ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| التمكين  | `INPUT_SANITIZER_ENABLED`                                                                                  | `true`            | عندما تكون القيمة `false`، يتوقف حاجز الحماية مبكرًا.                                                                                                                                                   |
| الوضع    | `INJECTION_GUARD_MODE` / `INPUT_SANITIZER_MODE`                                                            | `warn`            | سياسة الحقن: `block` أو `warn` أو `log`. (تُقبل `redact` للتوافق مع الإصدارات السابقة، لكنها **لا** تزيل نص الحقن؛ تتحكم `PII_REDACTION_ENABLED` في إعادة كتابة معلومات تحديد الهوية الشخصية في الطلب.) |
| حد المنع | خيار `blockThreshold` / `INPUT_SANITIZER_BLOCK_THRESHOLD` (الاسم البديل `INJECTION_GUARD_BLOCK_THRESHOLD`) | `high`            | الحد الأدنى لمستوى الخطورة المطلوب للمنع. يكون المستوى المتوسط للمراقبة فقط افتراضيًا.                                                                                                                  |

**أسبقية الوضع** (`getMode`): ‏`options.mode` الخاص بالمتصل ←
تجاوز **علامة ميزة قاعدة البيانات** لـ `INJECTION_GUARD_MODE` (لوحة المعلومات ← الإعدادات ←
علامات الميزات) ← متغير البيئة `INJECTION_GUARD_MODE` ← متغير البيئة `INPUT_SANITIZER_MODE` ←
`warn`. ولذلك يتغلب التجاوز من لوحة المعلومات على متغيرات البيئة، بحيث تتحكم واجهة
علامات الميزات في حاجز الحماية قيد التشغيل مباشرةً (من دون إعادة تشغيل). قراءة قاعدة البيانات آمنة عند الفشل:
فإذا حدث خطأ، يعود حاجز الحماية إلى السلوك المستند إلى متغيرات البيئة، وعندما لا يكون هناك
تجاوز مضبوط، يكون السلوك مطابقًا تمامًا للحل المستند إلى متغيرات البيئة فقط.

مصادر الاكتشاف:

1. ‏`sanitizeRequest()` من `@/shared/utils/inputSanitizer` (مجموعة أدوات الكشف المشتركة
   المستخدمة في مواضع أخرى من خط المعالجة).
2. ‏`DEFAULT_GUARD_PATTERNS` المضمّنة (حاليًا `system_override_inline` و
   `markdown_system_block`، وكلاهما بدرجة خطورة `high`).
3. أنماط `customPatterns` الاختيارية التي تُمرّر عبر خيارات المُنشئ (سلاسل نصية، أو تعبيرات نمطية،
   أو سجلات `{ name, pattern, severity }`).

عندما يكون `mode === "block"` **و** يطابق اكتشاف واحد على الأقل حد
الخطورة، يعيد `preCall` القيمة `{ block: true, message: "Request rejected:
suspicious content detected" }`. في وضعي `warn`/`log`، يسجّل حاجز الحماية الحدث لكنه
يسمح بالاستدعاء. وتُصدَّر أيضًا الدالة المساعدة المشتركة `evaluatePromptInjection()`
للمتصلين الذين يحتاجون إلى تقييم المطالبات من دون المرور عبر السجل.

**حد الفحص (v3.8.20):** لا يفحص الكاشف سوى **أول 16 KB** من
نص المطالبة المدمج — `MAX_INJECTION_SCAN_BYTES = 16 * 1024` (16 384 بايت) في
`src/shared/utils/inputSanitizer.ts`. تنفّذ كل من `detectInjection()` و
`evaluatePromptInjection()` العملية `slice(0, MAX_INJECTION_SCAN_BYTES)` قبل تشغيل
حلقة الأنماط. توجد توجيهات الحقن بالقرب من بداية الإدخال، ولذلك يحد هذا
من استهلاك وحدة المعالجة المركزية/جامع البيانات المهملة الناتج عن التعبيرات النمطية في الحمولات التي يبلغ حجمها مئات الكيلوبايت، من دون إضعاف الاكتشاف (راجع
#3932، #4041).

### أداة إخفاء بيانات الاعتماد (`credentialMasker.ts`)

تعمل في **كلتا** المرحلتين، وتأتي أخيرًا في السلسلة الافتراضية (الأولوية `95`). تحجب
الأنماط المعروفة لمفاتيح API / الرموز السرية من الحمولة الصادرة (محتوى
الرسائل، ووسائط استدعاءات الأدوات، ونتائج الأدوات) **ومن** استجابة المزوّد، بحيث لا
تتسرّب بيانات اعتماد ملصقة في مطالبة (أو يعيد ناتج أداة ترديدها)
إلى المزوّد الخارجي أو مرة أخرى إلى العميل.

- **بالاشتراك فقط**، وفق النهج نفسه المتبع في تنقيح معلومات التعريف الشخصية (قاعدة صارمة مجاورة للقاعدة رقم 20):
  تكون معطّلة ما لم يكن `settings.credentialRedactionEnabled === true` **أو**
  `CREDENTIAL_REDACTION_ENABLED=true`. عند تعطيلها، لا يقوم حاجز الحماية بأي إجراء —
  فلا يحظر مطلقًا ولا يعيد الكتابة مطلقًا.
- تجتاز `redactCredentials()` شجرة الحمولة/الاستجابة كاملةً (`walkValue()`،
  مع حماية من تلويث النماذج الأولية، وأمان من الدورات عبر `WeakSet`) وتستبدل التطابقات
  بعنصر نائب بالتنسيق `[REDACTED:<type>]`، مع استنساخ الفروع التي تغيّرت فعليًا فقط.
- تغطي `CREDENTIAL_PATTERNS` مفاتيح موفّري نماذج اللغة الكبيرة (OpenAI، OpenAI-proj،
  Anthropic، Google، Hugging Face، Replicate)، ورموز VCS/SaaS المميّزة (GitHub، Slack،
  Linear، Notion، npm، Postman، Discord)، ومفاتيح الدفع (Stripe، Square)، ومفاتيح
  الخدمات السحابية (مفتاح وصول AWS، Twilio، SendGrid، Mailgun)، والمفاتيح الخاصة /
  رموز JWT، وسلاسل الاتصال المتضمنة لبيانات اعتماد (`mongodb://user:pass@...`، إلخ)،
  ونمطًا عامًا لقيم ترويسات `Authorization`/`x-api-key`/`api-key`/`apikey`.
  تُنقّح المفاتيح التي تتخذ هيئة الترويسات (`authorization`، `x-api-key`، `api-key`،
  `apikey`) بنيويًا (القيمة فقط، مع الحفاظ على بادئة المخطط مثل
  `Bearer `/`Basic `) بدلًا من استخدام التعبير النمطي النصي العام.
- لا يحظر حاجز الحماية مطلقًا؛ بل يعيد الكتابة فقط (`modifiedPayload` /
  `modifiedResponse`) ويضيف بيانات وصفية (`meta.credentialsRedacted`، `meta.count`).

حاجز منع الانحدار: `tests/unit/credential-masker-guardrail.test.ts`.

## العقد الأساسي (`base.ts`)

```typescript
class BaseGuardrail {
  enabled: boolean;
  name: string;
  priority: number;

  constructor(name: string, options?: { enabled?: boolean; priority?: number });

  async preCall(payload: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;

  async postCall(response: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;
}

interface GuardrailResult<TValue = unknown> {
  block?: boolean; // تؤدي القيمة true إلى إيقاف السلسلة فورًا
  message?: string; // تظهر عند الحظر
  meta?: Record<string, unknown> | null;
  modifiedPayload?: TValue; // تُرجعها preCall لإعادة كتابة الطلب
  modifiedResponse?: TValue; // تُرجعها postCall لإعادة كتابة الاستجابة
}

interface GuardrailContext {
  apiKeyInfo?: Record<string, unknown> | null;
  disabledGuardrails?: string[] | null;
  endpoint?: string | null;
  headers?: Headers | Record<string, unknown> | null;
  log?: GuardrailLog | Console | null;
  method?: string | null;
  model?: string | null;
  provider?: string | null;
  signal?: AbortSignal;
  sourceFormat?: string | null;
  stream?: boolean;
  targetFormat?: string | null;
}
```

يشير حاجز الحماية إلى «عدم وجود تغيير» عبر إرجاع `void` أو `{}` أو
`{ block: false }`. يؤدي إرجاع `modifiedPayload`/`modifiedResponse` إلى استبدال
القيمة المتدفقة عبر السلسلة لحواجز الحماية اللاحقة.
يحمل `signal?: AbortSignal` دورة حياة المستدعي إلى حواجز الحماية. يُعد إلغاء الطلب استثناءً مقصودًا يسمح بالمتابعة عند الفشل: إذ تتوقف جسور الوسائط عن العمل وتُجري التنظيف دون استعادة الوسائط الخام إلى هدف معروف بأنه لا يدعمها.

## السجل (`registry.ts`)

يكشف `guardrailRegistry` الأحادي عن:

- `register(guardrail)` — يضيف (أو يستبدل بالاسم المعياري) حاجزًا و
  يعيد الترتيب حسب `priority` التصاعدي.
- `clear()` / `list()` — مساعدات إدارية.
- `runPreCallHooks(payload, context)` — يكرر الحواجز النشطة، يمرر
  الحمولة عبر `modifiedPayload`، ويتوقف عند أول `block: true`.
- `runPostCallHooks(response, context)` — نفس التدفق على جانب الاستجابة.
- `resetGuardrailsForTests({ registerDefaults })` — يمسح الحالة و
  يعيد تسجيل الإعدادات الافتراضية اختياريًا لعزل الاختبار النظيف.

يعيد كل من المشغلين `{ blocked, payload|response, results, guardrail?, message? }`
حيث `results` هي مصفوفة من سجلات `GuardrailExecutionResult` التي تتضمن
حقول `blocked`, `skipped`, `modified`, `error`, و `meta` لكل حاجز،
مفيدة للتتبع.

### تعطيل الحواجز لكل طلب

يقوم `resolveDisabledGuardrails({ apiKeyInfo, body, headers })` بتجميع قائمة
غير مكررة لأسماء الحواجز التي يجب تخطيها للطلب الحالي. المصادر (جميعها اختيارية، وجميعها مدمجة):

- `apiKeyInfo.disabledGuardrails`
- نص الطلب `disabledGuardrails` (على المستوى الأعلى)
- نص الطلب `metadata.disabledGuardrails`
- الرأس `x-omniroute-disabled-guardrails` (أو القديم
  `x-disabled-guardrails`)

يمكن أن تكون القيم مصفوفات من السلاسل أو سلسلة مفصولة بفاصلة؛ يتم
تطبيع الأسماء إلى صيغة kebab-case بالأحرف الصغيرة (`pii_masker` ← `pii-masker`).
يتم تمرير النتيجة عبر `context.disabledGuardrails` إلى السجل، الذي يتخطى
الحواجز المطابقة (`skipped: true` في `results`).

لكل طلب يمر عبر `src/sse/handlers/chat.ts` و `open-sse/handlers/chatCore.ts`:

1.  يقوم `resolveDisabledGuardrails(...)` بإنشاء قائمة التخطي من مفتاح API، والنص الأساسي، والرؤوس.
2.  يقوم `guardrailRegistry.runPreCallHooks(body, ctx)` بتشغيل الحواجز الأمنية بترتيب تصاعدي للأولوية:
    - يتم تسجيل الحواجز الأمنية المعطلة على أنها `skipped`.
    - قد يقوم `preCall` لكل حاجز أمني بإعادة كتابة الحمولة عبر `modifiedPayload`.
    - أول `block: true` يقطع السلسلة ويعيد المعالج استجابة رفض الحاجز الأمني.
3.  تتدفق الحمولة (التي قد تكون أعيدت كتابتها) إلى توجيه التحرير والسرد والإرسال الأولي.
4.  بعد تجميع الاستجابة، يقوم `guardrailRegistry.runPostCallHooks(...)` بتشغيل نفس السلسلة على الاستجابة. `block: true` هنا يسقط الاستجابة الأولية.

يتم تسجيل الحواجز الأمنية التي تثير خطأ بـ `error: <message>` ويتم تسجيلها عبر `logger.warn`، لكن السلسلة تستمر — تصميم يسمح بالفشل المفتوح.

## التكوين

متغيرات البيئة التي تقرأها الحواجز الأمنية المدمجة:

| المتغير | يستخدم بواسطة | التأثير |
| `INPUT_SANITIZER_ENABLED` | `prompt-injection` | تعيين `false` لتعطيل الكشف بالكامل. |
| `INPUT_SANITIZER_MODE` | `prompt-injection` | سياسة الحقن: `warn` (تحذير)، `block` (حظر)، أو `log` (تسجيل). القيمة القديمة `redact` لا تعيد كتابة نص الحقن. |
| `INJECTION_GUARD_MODE` | `prompt-injection` | وضع حماية الحقن؛ وهو أيضًا علامة ميزة قاعدة بيانات **تتجاوز** متغيرات البيئة (قاعدة البيانات > البيئة). |
| `INPUT_SANITIZER_BLOCK_THRESHOLD` | `prompt-injection` | الحد الأدنى للخطورة الذي يرفضه `MODE=block`: `high` (مرتفع، افتراضي)، `medium` (متوسط)، أو `low` (منخفض). |
| `INJECTION_GUARD_BLOCK_THRESHOLD` | `prompt-injection` | اسم مستعار قديم لـ `INPUT_SANITIZER_BLOCK_THRESHOLD`. |
| `PII_REDACTION_ENABLED` | `pii-masker` | عندما يكون `true`، يتم تنقيح معلومات التعريف الشخصية (PII) للطلب (بصرف النظر عن وضع الحقن). |
| `PII_RESPONSE_SANITIZATION` / `_MODE` | `pii-masker` (downstream) | يتحكم في سلوك قناع الاستجابة. |

تقرأ الحواجز الأمنية لـ Modality Bridge التكوين في وقت التشغيل من مخزن الإعدادات المدعوم بقاعدة البيانات (`getSettings()`)، وليس من متغيرات البيئة. المفاتيح الأساسية لـ Vision هي `modalityBridgeVisionEnabled`, `modalityBridgeVisionMode`, `modalityBridgeVisionModel`, `modalityBridgeVisionTaskAware`, `modalityBridgeVisionPrompt`, `modalityBridgeVisionTimeout`, `modalityBridgeVisionMaxImages`, `modalityBridgeVisionMaxChars`, `modalityBridgeCacheEnabled`, `modalityBridgeCacheTtlMinutes`, و `modalityBridgeCacheMaxEntries`. يتم قبول المفاتيح القديمة `visionBridge*` فقط كخيار احتياطي للقراءة لمرة واحدة كما هو موثق؛ تستخدم عمليات الكتابة في لوحة التحكم المفاتيح الأساسية. توجد القيم الافتراضية ومحلل الاحتياطي في `src/shared/constants/modalityBridgeDefaults.ts`، مع الاحتفاظ بالثوابت القديمة في `src/shared/constants/visionBridgeDefaults.ts`.

يستخدم الصوت `modalityBridgeAudioEnabled`, `modalityBridgeAudioModel`, `modalityBridgeAudioTimeout`, و `modalityBridgeAudioMaxClips`, بالإضافة إلى إعدادات `modalityBridgeCache*` المشتركة. لا يحتوي الصوت على خيار احتياطي للمفاتيح القديمة لأن هذه المفاتيح تم تقديمها مع مخطط Modality Bridge.

يستخدم الفيديو `modalityBridgeVideoEnabled`, `modalityBridgeVideoAnalysisMode`, `modalityBridgeVideoModel`, `modalityBridgeVideoFrameCount`, `modalityBridgeVideoSamplingPolicy`, `modalityBridgeVideoMaxVideos`, و `modalityBridgeVideoTimeout`, بالإضافة إلى إعدادات `modalityBridgeCache*` المشتركة. يتم تعطيله افتراضيًا لأن FFmpeg/ffprobe هي تبعيات تشغيلية اختيارية، وإضافة تسميات الإطارات تزيد من زمن الاستجابة وتكلفة النموذج.

## حواجز حماية مخصصة

```typescript
import { BaseGuardrail, guardrailRegistry } from "@/lib/guardrails";

class BudgetGuardrail extends BaseGuardrail {
  constructor() {
    super("budget", { priority: 50 });
  }

  async preCall(payload, ctx) {
    if (ctx.apiKeyInfo?.budgetExceeded) {
      return { block: true, message: "Daily budget exceeded" };
    }
    return { block: false };
  }
}

guardrailRegistry.register(new BudgetGuardrail());
```

الخطوات:

1.  أنشئ `src/lib/guardrails/myGuardrail.ts` يوسع `BaseGuardrail`.
2.  نفّذ `preCall` و/أو `postCall`.
3.  سجّل إما وقت الاستيراد (ادفع من `registerDefaultGuardrails`) أو
    استدعِ `guardrailRegistry.register(...)` في وقت التشغيل — يحل السجل محل
    أي حاجز حماية سابق بنفس الاسم المعياري.
4.  أضف اختبارات تحت `tests/unit/` (أمثلة موجودة:
    `tests/unit/guardrails-registry.test.ts`,
    `tests/unit/prompt-injection-guard.test.ts`,
    `tests/unit/guardrails/visionBridge.test.ts`).

## تغطية مسار حماية الحقن والاختبار الأحمر (المرحلة 8 · الكتلة D)

يغطي حارس الحقن (`createInjectionGuard` / `withInjectionGuard`) جميع المسارات
التي تقبل مطالبات المستخدم. وهو يحترم `INJECTION_GUARD_MODE` (الافتراضي `warn` = تسجيل فقط؛
`block` = يعيد HTTP 400 `SECURITY_001`).

| النوع      | المسارات                                                                                                                                             | الوضع الافتراضي |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | --------------- |
| نص (موجود) | `/v1/chat/completions`, `/v1/completions`, `/v1/relay/chat/completions`                                                                              | warn            |
| توليدي     | `/v1/messages`, `/v1/responses`, `/v1/images/generations`, `/v1/images/edits`, `/v1/videos/generations`, `/v1/music/generations`, `/v1/audio/speech` | warn            |
| بيانات     | `/v1/embeddings`, `/v1/rerank`, `/v1/search`, `/v1/moderations`                                                                                      | warn            |

تغطية استخراج النص (`extractMessageContents`) تشمل `messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system`.

**الفريق الأحمر (ليلي، `nightly-llm-security.yml`):** يتحقق promptfoo من أن كل مسار يحظر
مجموعة OWASP-LLM في `INJECTION_GUARD_MODE=block`؛ يقوم garak بتشغيل الفحوصات (يتخطى بدون سر).
يتم تضمين `moderations` من أجل الاتساق — يمكن للمشغلين في وضع الحظر إعفائها عبر
`resolveDisabledGuardrails`.

يحتوي سير العمل الليلي (`.github/workflows/nightly-llm-security.yml`، cron +
التشغيل اليدوي) على وظيفتين:

- **`promptfoo-guard` (حظر)** — يشغل `promptfoo eval -c promptfooconfig.yaml`
  مع `INJECTION_GUARD_MODE=block`. تؤكد كل حالة عدائية (مثل "تجاهل جميع
  التعليمات السابقة..."، اختراقات على غرار DAN) أن الاستجابة تحمل
  `error.code === "SECURITY_001"`، أي أن الحارس رفض الطلب بالفعل.
- **`garak` (استشاري)** — يشغل garak `--probes promptinject,dan,leakreplay`
  مقابل مثيل OmniRoute محلي (`http://localhost:20128/v1`). يتم التحكم فيه بواسطة
  سر مزود (`PROMPTFOO_PROVIDER_KEY`)؛ يتخطى بأمان ويتم إلحاقه بـ
  `|| true`، لذلك يتم الإبلاغ عنه دون فشل CI.

تغطية مساعد الحارس (`createInjectionGuard` / `withInjectionGuard`)
تمتد عبر كل مسار `/v1` يحمل مطالبة؛ يتم سحب نص المطالبة من
`messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system` بواسطة
`extractMessageContents()` في `src/shared/utils/inputSanitizer.ts`.
